# Control Tower Live Integration — Design

Backlog Stream L. Ports the validated `feat/real-data-dry-run` branch (built 2026-09-19, verdict **SAFE TO CUT OVER**, verified against the live Jello Control Tower Sheet: R1–R7 all matched except one confirmed Sheet-side bug) onto current `main`, which has diverged by 118 commits since — five full hardening streams (Security, Performance, Ledger Completion, Sales Plan, three-lens review) plus three more (Operational, Engineering, Product coherence) all landed after the dry-run branch forked.

## Why this is a port, not a redesign

Every business rule, mapping, and algorithm in this doc was already validated against real data on 2026-09-19 and is preserved **verbatim** — this design's own job is only to identify what changed on `main` since the fork and adapt the integration points accordingly. The source of truth for every mapping/convention/tolerance below is `docs/2026-09-19-real-data-dry-run-design.md` (on the `feat/real-data-dry-run` branch, not merged) plus the decisions Artem made the same day (`docs/dryrun/2026-09-19/report.md` final state, `docs/BACKLOG.md`/`docs/BUILD-HISTORY.md` deltas on that branch) — read both before touching any task in the implementation plan. Do not re-derive the Sheet mappings, the backorder-aware FIFO formula, or the tolerance/variance rules from first principles; they are already correct.

**Final validated result** (after Artem's same-day decisions, the target this port must reproduce or exceed): R1 SOH-today 6/6, R2 SOH-by-day 576/576, R3 Daily COGS 570/570, R4 landed cost 23/24 (1 confirmed Sheet-side Apps Script bug, unaffected by platform correctness), R5 payments 22/22, R6 transactions 3/3, R7 sales actuals 6/6, 0 quarantines, 0 untransferable links, 20/20 payments and 20/20 transaction links transferred.

## What changed on `main` since the fork (2026-09-19 → today) that this port must account for

Verified by reading current `main` directly, not assumed:

1. **`server/inventoryLedger.ts`/`server/salesPlan.ts` FIFO logic was unified, AND `computeFifoCogs`/`LandedBatch`/`SaleEvent`/`FifoCogsResult` were deleted as dead code** (Backlog Stream J) — confirmed by reading current `server/landedCost.ts` in full: none of the four exist any more. This is **still orthogonal** to what this port adds — `computeFifoDailySeries` (backorder-aware, retroactive-pricing Daily COGS series) was *always* designed as a separate function from the dashboard's own COGS path (the original design's own Non-Goals: "`server/salesPlan.ts`'s `getDailyCogs` is not switched to the new series here") — but it cannot resurrect `LandedBatch`/`SaleEvent` as import targets, since Stream J correctly identified and removed them as genuinely dead at the time. Port `computeFifoDailySeries` with its own local, minimal input types (`{ qty: number; unitCost: number; date: Date }` for receipts, `{ qty: number; date: Date }` for sales — the exact shape the deleted types had, just declared fresh in this file rather than reusing a name that no longer exists) rather than reaching into `server/inventoryLedger.ts`'s `FifoBatch` (a different, unrelated type introduced by the same unification, with its own shape `{ qty, unitCost, date, sourceRef }` for a different caller's needs) or reintroducing a cross-file dependency `landedCost.ts` doesn't otherwise have.
2. **`recordSalesActual` still has no `dbClient` parameter on `main` today** — confirmed by reading `server/salesPlan.ts`. The original design's port item ("gains an optional `dbClient` parameter... inside the migration transaction they would not see the rows just inserted") is still needed and not yet done on `main`. Port this exactly as designed.
3. **`markPaymentPaid`/`matchTransactionToPayment` evolved independently and are now *better* than what the port needed.** The original design wanted these to "gain an optional `dbClient` parameter." `main` already went further (Priority-1 Operational cleanup): `markPaymentPaid` is now a thin wrapper around `markPaymentPaidCore(id, opts, dbClient)`, which already accepts a `dbClient`. This port's migration code does not currently call either function at all (payments are only ever created via `createExpectedPayment`, never marked paid, in the version on `main` today) — the port needs to add the paid-flag/match-transfer logic from scratch using the **current** `markPaymentPaidCore`/`matchTransactionToPayment` signatures, not the dry-run branch's older ones. `matchTransactionToPayment` today requires a `reasonCategory`/`changedBy` in its `opts` — the migration will need a fixed reason (e.g. `"other"`, note `"migrated from Control Tower"`) and the same migration system user used elsewhere.
4. **`server/dbClient.ts`'s UTC-pinning already exists, via a different (correct) mechanism.** `main` pins every new pool connection's session timezone via a `pool.on("connection", ...)` handler running `SET time_zone`, not the dry-run branch's `{ uri, timezone: "Z" }` connection option. **Do not port the dry-run branch's `dbClient.ts` change** — the design doc's own Open Questions flagged this exact option as unverified, and Backlog Stream E's implementer independently discovered it "turned out to do nothing" against this stack and replaced it with the session-handler approach already on `main`. The port needs zero changes to `dbClient.ts`.
5. **`scripts/reconcile-migration.ts` already has a migration-system-user pattern**, added by Backlog Stream J's Engineering hardening for an unrelated reason (the `purchase_orders.createdBy`/`shipments.createdBy` FKs added that same stream). `ensureMigrationUser()` (get-or-create `migration@accommerce.system`, role `viewer`, inside the migration's own transaction) already exists on `main` and should be **reused as-is** — do not add a second, different system-user mechanism from the dry-run branch.
6. **Every money/share column is now `decimal`, not `varchar`** (Backlog Stream J). The migration/export code builds every one of these as a JS string (`String(...)`, template literals, `.toFixed(...)`) exactly as it always did — Drizzle's `decimal(..., { mode: "string" })` keeps that contract identical on both read and write, so no export/transform code needs to change for this. The one thing worth re-verifying (not assuming) during implementation: that every decimal value the exporter produces round-trips at the new columns' precision (the design doc's own reconciliation tolerances — R4's `0.00006`, R3's `0.01` — already have more headroom than any column's new scale, e.g. `decimal(18,6)` for `unitCost`, so this is expected to be a non-issue, but the port's tests should prove it rather than assume it).
7. **`skus` gained `leadTimeDays`/`safetyStockDays`** (Backlog Stream K, Product coherence), both `NOT NULL DEFAULT`. The Sheet's SKU Master tab has no equivalent column (confirmed in the original design's own "Source of Truth" table: "carton kg/units, vendor" only) — the migration creates SKUs via the existing `ensureSku` helper, which never sets these fields, so they correctly fall back to the schema defaults (66/14). No mapping needed; explicitly not a gap.
8. **`getShipmentLandedUnitCost` (`server/landedCost.ts`) still has no `dbClient` parameter** — confirmed by reading the current function signature (`shipmentId: number` only, every internal query hardcoded to the pool-backed `db`). The real landed-cost reconciliation wiring (scope item 6 below) needs this to run inside the migration's own transaction and see the shipment/line-item rows just inserted, not the pool's separately-committed view — port the same `dbClient: DbClient = db` addition the original design specified, threading it through every internal query in the function. Its return shape has also gained a `lineItemId` field since the fork (from Backlog Stream G's ledger-completion work, mapping landed cost per line item rather than per SKU, since one shipment can have two lines for the same SKU) — the reconciliation code consuming this return value needs to key on `lineItemId` where the original design assumed `skuId` alone was unique per shipment, or continue to use `skuId` where a shipment's lines are already known to be one-per-SKU (verify which is actually true for the real Sheet data during implementation, not assumed).
9. **`scripts/reconcile-migration.ts` on `main` today is still the original Stream-B-era version** — JSON-file input only (`RunMigrationInput` with `ledgerRows`/`poRows`/`shipmentRows`/`paymentRows`/`transactionRows`/`sheetTotals`/`landedCostTotals`), `landedCostTotals` still throws if non-empty ("not yet wired to a real data source"), no paid-flag handling, no transaction-matching, no sales-actuals/sales-plan writes, no pooled-container merging. This confirms the bulk of the dry-run branch's `reconcile-migration.ts`/`migrate-from-sheet.ts` extensions (§2 of the original design, plus the same-day pooled-container/variance-tier decisions) are still needed in full — this is the single largest task in the implementation plan.

## Scope

Port, in dependency order (pure utilities first, migration-script extensions next, new orchestration layer last):

1. **Pure, self-contained new files** (no dependency on anything that changed on `main`): `scripts/control-tower/csv.ts`, `gviz.ts`, `snapshot.ts`, `scripts/control-tower/fixtures/*` (real, bank-column-scrubbed Sheet snapshot, captured 2026-09-19 — reused as-is, this is real validated data, not synthetic). Direct port, no adaptation.
2. **Backorder policy** — `server/inventoryLedger.ts` gains `ALLOW_BACKORDERS_SETTING` (`app_settings` key `allow_backorders`), consulted only on the path that would otherwise throw (per-instance, zero overhead for instances that never go negative). Direct port onto current `recordLedgerEvent` (the guard's shape is unchanged by the FIFO unification — only `getRemainingBatches`/`getDailyCogsForRange`, not `recordLedgerEvent`, were touched by that stream).
3. **Backorder-aware Daily COGS series** — `server/landedCost.ts` gains `computeFifoDailySeries` (the retroactive-pricing, landing-gated FIFO series matching the Sheet's own `buildDailyCogs` convention exactly, including the 2026-09-17 fix), with its own fresh local input types per adaptation point 1 above (not a resurrection of the deleted `LandedBatch`/`SaleEvent`/`computeFifoCogs`). `getShipmentLandedUnitCost` in the same file gains the `dbClient` parameter and `lineItemId`-aware handling per adaptation point 8.
4. **`recordSalesActual` gains an optional `dbClient` parameter** in `server/salesPlan.ts` (adaptation point 2 above), joining an existing transaction instead of opening a nested one when passed one explicitly — same pattern already established across this codebase for every other core/wrapper transaction function.
5. **`migrate-from-sheet.ts` transform extensions**: `PaymentSheetRow` gains `paid`/`paidDate`; `ShipmentSheetRow` gains `plannedDepartDate`/`actualDepartDate`/`plannedArrivalDate`/`actualArrivalDate` and pooled-container merging (rows named `<prefix>Container<N>-<SKU>` collapse into one shipment with N lines, sharing dates/warehouse-consistency validation, mismatched rows quarantined); `TransactionSheetRow` gains `matchedRef`; new `salesActualRows`/`salesPlanRows` transform functions. Every mapping rule (status maps, share computation, fx derivation, unit-price/freight/duty derivation) ports verbatim from §2 of the original design — copy the exact field mappings, not a reinterpretation of them.
6. **`reconcile-migration.ts`'s `runMigration` extensions**: paid-flag handling via `markPaymentPaidCore` (adapted per point 3 above — not the dry-run branch's `markPaymentPaid(..., tx)` call, which no longer matches current `main`'s signature); transaction-to-payment matching via `matchTransactionToPayment` with the current `opts` shape; sales-actuals/sales-plan writes via `recordSalesActual(..., tx)`/`createSalesPlanEntry(..., tx)`; pooled-container payment-slot summing; the 1%-then-5%-variance-tier link-transfer rule with `paidAmount` recorded separately from `expectedAmount` (verbatim from the decided-rules delta); real landed-cost reconciliation wired to `getShipmentLandedUnitCost` on the transaction client (removing the old "throws if landedCostTotals is non-empty" guard, whose entire reason for existing — unknown real column names — no longer applies). `ensureMigrationUser()` stays exactly as it is on `main` today (adaptation point 5) — every new write (payments, sales actuals/plan) attributes to it via the same pattern already used for POs/shipments.
7. **`reconcile.ts`/`targets.ts`/`export.ts`/`report.ts`/`classifications.ts`** (the R1–R7 reconciliation-target readers and markdown report): direct port. These depend only on the functions ported in steps 2-6 above and on already-stable read paths (`getSoh`, `getShipmentLandedUnitCost`) — no `main`-side drift affects their own logic, only their imports need to resolve against current file locations (unchanged) and current function signatures (only `computeFifoDailySeries`/`getShipmentLandedUnitCost` are called across this boundary, both ported/stable per steps 3 and unchanged respectively).
8. **`scripts/run-dryrun.mjs`, `scripts/parallel-run.mjs`, `ops/*`**: direct port of the orchestrator, the daily parallel-run script, and the launchd job definition. `scripts/run-dryrun.mjs` should be renamed `scripts/run-dryrun.ts` to match Backlog Stream J's own `.mjs`→`.ts` rename (the same `tsc`-blind-spot fix applies here — this is a **new** script being added, so it should be born `.ts`, not `.mjs`, matching the now-established convention rather than reintroducing the exact gap Stream J just closed). Same for `scripts/parallel-run.mjs` → `scripts/parallel-run.ts`.
9. **`package.json`**: add `dryrun`/`parallel-run` scripts (adjusted for the `.ts` rename in step 8).
10. **Docs**: this design doc plus a plan; `README.md`'s Current Status gains the dry-run result (honestly — it already ran successfully once, against a live Sheet, before `main` had today's full hardening; this port's own final task re-runs it against current `main` to confirm the result still holds, and that re-run's actual output is what gets committed, not the original 09-19 numbers copied blind).

## Explicitly out of scope (matching the original design's own Non-Goals, still correct)

- Deploying to Railway, or any actual cutover decision — this stream produces a verdict and the tooling to reach one; going live stays a separate, explicitly-gated decision with Artem.
- Swapping `getDailyCogs`/`getMoneyDashboard` to `computeFifoDailySeries` — still a deliberate non-goal; the dashboard's own FIFO path and the reconciliation tooling's FIFO path are intentionally decoupled.
- Multi-currency landed cost — the Sheet expresses everything in EUR for this instance; the platform's single-reporting-currency assumption still holds and is asserted, not solved.
- Fixing the one confirmed Sheet-side bug (Landed Cost Summary restates a qty on the Mutual-PO2-Delivered Mixer line) — that's Artem's Apps Script, not this platform.
- Any new schema change beyond what already landed on `main` — the backorder flag still lives in `app_settings`, exactly as designed.

## Testing requirements

Every test named in the original design's §8 ports directly (CSV parser edge cases, normalizer rejections, each export mapping against the real fixture rows including the pooled-container merge and its conflicting-variant quarantine case, `computeFifoDailySeries` hand-computed cases plus the golden test against the real Daily COGS fixture, the backorder-policy guard test, the scale test). Additionally, since this is a port onto a schema that has changed:

- A new round-trip check (not in the original design, needed because of adaptation point 6 above): seed one payment/shipment-cost/transaction through the real migration path and confirm every decimal-typed field the exporter wrote survives at its full precision through the now-`decimal` columns — reusing the same pattern Backlog Stream J's own `decimalMigration.test.ts` established.
- The final task must **actually re-run** `pnpm dryrun` against the live Sheet (or, at minimum, the committed real fixture snapshot in offline-replay mode if live access isn't available in this environment) and commit the real output report — not the original 09-19 report copied over. If the re-run's result differs from the original (e.g. Sheet data has changed since, or a genuine platform regression surfaces), that is a real finding to report, not something to paper over by keeping the old report.
- Full suite stays green (`pnpm test`, currently 232) and `pnpm check` clean throughout — this port's own test additions run on top of, not instead of, the existing suite.
